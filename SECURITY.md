# Security Policy

## Supported Versions

Security updates are provided for the most recent version of UserInfoDataEntryForm.

| Version | Supported          |
|---------|--------------------|
| Main    | :white_check_mark: |

## Reporting a Vulnerability

If you discover a security vulnerability in UserInfoDataEntryForm, please report it
privately. Do not open a public GitHub issue, or share proof-of-concept code publicly before the issue has
been resolved.

Report vulnerabilities using one of the following methods:

- Email: yours.truly.official@icloud.com

Please include as much of the following information as possible:

- A clear description of the vulnerability.
- Steps needed to reproduce the issue.
- The affected command, feature, version, or commit.
- The potential impact, such as unauthorized access, data disclosure, privilege
  escalation, server disruption, or token exposure.
- Proof-of-concept code, screenshots, logs, or recordings, if safe to provide.
- Suggested mitigations, if you have them.

Do not include API keys, private user
data, or other sensitive credentials in your report. If credentials may have
been exposed, revoke or rotate them immediately and tell us what was exposed.

## Our Response Process

After receiving a report, we aim to:

1. Acknowledge receipt within 7 days.
2. Review and validate the report.
3. Provide updates when practical during investigation.
4. Fix, mitigate, or explain why the issue is not considered a vulnerability.
5. Coordinate disclosure after a fix is available, when appropriate.

Response and resolution times may vary depending on severity, reproducibility,
and maintainer availability.

## Scope

This policy applies to:

- The source code in this repository.

This policy does not apply to:

- Third-party forks, self-hosted installations, or unofficial deployments.
- Third-party services, libraries, hosting providers, or dependencies, unless
  the issue is caused directly by this project's implementation.
- Social engineering, phishing, spam, denial-of-service attacks, or actions
  that disrupt service availability.
- Reports involving unauthorized access to accounts.
